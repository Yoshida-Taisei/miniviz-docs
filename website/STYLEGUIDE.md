# ドキュメント執筆・編集ルール

このプロジェクト（Docusaurus 3）におけるドキュメントの構成と執筆ルールです。

## 1. 構成ルール

### サイドバー構造
- **はじめに**: プロジェクトのトップ（`intro.mdx`）。
- **クイックスタート**: 最小限の手順で動作確認するためのガイド。
- **ユースケース**: デバイスや目的別の実践ガイド。
  - センサーデータを送る（温湿度など）
  - 画像を送る
  - 連携ガイド（SwitchBotなど外部サービス）
- **API**: 技術リファレンス。
- **付録：サンプルコード**: 各ガイドで使用したコードの完全版をまとめたセクション。

### 記事の統合
- 解説（手順・配線）とサンプルコードは、原則として **1つの記事内** にまとめます。
- サンプルコードは記事の巻末に配置し、Docusaurus の `Tabs` を使って言語別に切り替えられるようにします。

## 2. 執筆ルール

### タイトル（H1）
- **「（デバイス名）で（何をするか）」** の形式で統一します。
  - 例: `Raspberry Pi で温湿度データを送る`
  - 例: `Raspberry Pi × USBカメラで画像を送る`
- サイドバーの表示名は、原則としてこの H1 タイトルがそのまま使用されます。

### 不要なセクションの排除
- **「Minivizとは？」セクション**: 共通の紹介文は各記事には含めず、`intro.mdx` に任せます。
- **手動の目次**: Docusaurus が右サイドバーに自動生成するため、記事内の Markdown による目次は削除します。
- **冒頭のサンプルコード案内**: サンプルコードは巻末に統合されているため、冒頭で別ページへ誘導するようなリンクや案内は不要です。

### 装飾と見栄え
- **アドモニション（Admonitions）の活用**: 重要な補足、Tips、注意書きなどは、Docusaurus のアドモニション機能を使って装飾します。
  - `:::info`: 補足情報
  - `:::tip`: 役立つヒントや推奨設定（例：ボーレート設定、反映待ち時間など）
  - `:::caution`: 注意事項（例：プラン制限など）
- **簡潔な導入**: 「ここで行うこと」セクションなどは、箇条書きよりも簡潔な文章で記述し、必要に応じてアドモニションで補足します。

### サンプルコードの記述
- Docusaurus の `Tabs` コンポーネントを使用します。
- コードブロックには必ず言語指定（`python`, `cpp` など）を行い、シンタックスハイライトを有効にします。

```markdown
import Tabs from '@theme/Tabs';
import TabItem from '@theme/TabItem';

<Tabs>
  <TabItem value="python" label="Python" default>
    ```python
    # コード
    ```
  </TabItem>
</Tabs>
```

## 3. 翻訳（i18n）ルール
- 日本語版は `i18n/ja/docusaurus-plugin-content-docs/current/` 配下に配置します。
- サイドバーのカテゴリ名などの翻訳は `i18n/ja/docusaurus-plugin-content-docs/current.json` で管理します。
